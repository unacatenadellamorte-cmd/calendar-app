- (decision) 真実源は Supabase Postgres。クライアントはオフライン表示用のローカルキャッシュ(IndexedDB)を持つが書き込みは必ず Supabase 経由。防ぐ乖離: クライアントごとに別の真実を持ってしまう
- (decision) 外部カレンダーは一方向取り込みのみ(v1)。source=external の予定はアプリ内で編集・削除不可。書き戻し経路をコードに作らない。防ぐ乖離: 誰かが「ついでに」Google書き込みを足して双方向化し競合解決が無いまま壊れる
- (decision) Google provider_refresh_token はサーバー側(Supabase Vault / 暗号化テーブル)にのみ保存。クライアント・ローカルキャッシュ・ログに出さない。トークン交換と Calendar API 呼び出しは Edge Function のみ。根拠: Supabaseはプロバイダトークンを自動更新しない(web確認)
- (decision) 外部取り込みは Edge Function を pg_cron で定期実行 + ユーザーの「今すぐ取り込み」で同関数起動。冪等(外部イベントIDでupsert、消えたものは論理削除)。最終取り込み時刻・失敗をカレンダー単位で記録
- (decision) 優先度は単一の順序値(カレンダーごと、全体で一意)。『並び順』も『代表予定の選抜』も同じ優先度リストから導出する共有純関数に集約。UI・将来のウィジェット/通知はこの関数を呼ぶだけ。防ぐ乖離: 画面ごとに別の並べ方が実装される
- (decision) 代表予定の選抜は1つの純粋関数(入力: 予定 + カレンダー優先度 + 現在時刻 + 上限、出力: 順序付き代表予定)。副作用なし・プラットフォーム非依存の共有パッケージ。client と Edge Function の両方から使える
- (decision) 時刻は timestamptz(UTC)で保存、表示時にユーザーTZへ変換。終日予定は date 型(TZ無し)。防ぐ乖離: ローカル時刻保存とUTC保存が混在してシフトの日跨ぎ計算がずれる

- (decision) クライアント依存方向: UI → hooks/view-model → data-access(supabase-js + ローカルキャッシュ) → 外部。UIから直接 supabase-js を呼ばない。selection/pay-calc は純粋ドメイン(何も参照せず・どこからも参照可)
