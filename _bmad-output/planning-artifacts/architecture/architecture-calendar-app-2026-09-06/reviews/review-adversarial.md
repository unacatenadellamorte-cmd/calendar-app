# Adversarial review — アーキテクチャスパイン

*「AD をすべて守っても2つのユニットが非互換に組める」ペアを探す。Finalize 内の自己ゲート。*

## Verdict

4件の穴を発見、いずれもスパインに反映済み(AD-5 / AD-6 / AD-8 / Conventions を追記)。残る想定リスクは低。

## 見つけたペアと対応

| # | 互換に壊れるペア | 対応 |
|---|---|---|
| 1 | **優先度の重複採番** — フロント(FR-5/6 でローカルカレンダー作成)と取り込み Edge Function(FR-4 で外部カレンダー発見)が、それぞれ「最下位の優先度」を割り当てる。同時実行で同じ優先度になり、AD-5 の「一意」前提が崩れて選抜のタイブレークが不定に | **AD-5 を強化**: `(user_id, priority)` の unique 制約 + 採番/並べ替えを単一 RPC 経由に。両者がそれを呼ぶ |
| 2 | **選抜関数へ渡す形の不一致** — `packages/core` をフロント(camelCase)と Edge Function(Postgres 直読み snake_case)が共有。同じ `selectFeaturedEvents` に別形の入力が来て結果がずれる | **AD-6 を強化**: `packages/core` が正規入力型(camelCase / UTC)を定義、呼び出し側が変換してから渡す |
| 3 | **`now` の出所** — フロントはブラウザ時刻、将来の通知 Edge Function はサーバー時刻。関数内部で現在時刻を読むと2者で違う代表予定になる | **AD-6 を強化**: `now` は呼び出し側が渡す UTC 時点、関数内部で時刻を読まない |
| 4 | **シフト属性の消失** — シフト作成は `features/shifts`、汎用の予定編集は `features/calendar`。汎用編集がシフト予定を全置換すると `break_minutes`・`hourly_wage` が消える | **AD-8 を強化**: 汎用編集はシフト属性を触らない(部分更新)。シフト属性の編集経路は `features/shifts` のみ |

## 追加で確認したが穴ではなかった

- AD-2(書き戻し禁止)— レビュー/lint で担保する運用前提。コード上の強制はないが、v1 スコープでは許容。
- AD-1 のローカルキャッシュ — 論理削除の見落としが穴になりうるため Conventions に「`deleted_at` 除外を共通ヘルパで強制」を追記。
