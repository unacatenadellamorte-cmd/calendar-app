# Good-spine rubric — アーキテクチャスパイン

## Verdict

feature 高度の不変条件を必要十分に固定できている。lint 0 件。adversarial で見つけた4穴は反映済み。運用エンベロープ(デプロイ/環境/シークレット)もカバー。フロント形態が [ASSUMPTION] のまま残るが、AD 群はフロント形態に依存しない書き方で、epics へ進んで問題ない。

## チェック項目

| 項目 | 判定 | 補足 |
|---|---|---|
| 下位レベルの本当の乖離点を押さえ、漏れがない | 良 | データ所有(AD-1)・書き戻し禁止(AD-2)・資格情報(AD-3)・取り込み冪等(AD-4)・並び1か所(AD-5/6)・時刻(AD-7)・シフト=予定(AD-8)・レイヤ依存(AD-9/10) |
| 各 AD の Rule が強制可能で、述べた乖離を実際に防ぐ | 良 | AD-2 のみコード強制でなくレビュー運用前提(v1 許容) |
| Deferred に、2ユニットが乖離しうるものが無い | 良 | オフラインマージは「後勝ち + キュー順序」と明示。選抜規則は AD-6 の純関数で隔離 |
| 技術が現行確認済み | ほぼ良 | Vite マイナー未固定(形態未確定のため許容) |
| ブラウンフィールドと矛盾しない | N/A | greenfield。human-book の static-export 罠は回避方針に反映 |
| PRD の全 capability をカバー | 良 | Capability→Architecture Map に FR-1〜17 |
| 高度が持つ全次元が decided / deferred / open | 良 | パラダイム・境界・データ所有・状態変更・認証・デプロイ&環境・外部連携・テスト、いずれも記載。監視/コストは Deferred(規模相応) |

## 指摘(tail)

- **medium**: フロント形態(Vite SPA vs Next.js 16)が未確定。epics には影響しないが、最初のスプリント前に確定させたい。
- **low**: Vite / vite-plugin-pwa バージョン未固定。
- **low**: AD-2 はコードで強制されない(書き込み関数を「置かない」規律)。lint ルール化を検討。
