# PRD Quality Review — カレンダーアプリ(仮)

*Finalize 時のルーブリック走査(bmad-prd assets/prd-validation-checklist.md)。stakes = 個人プロジェクト → 将来一般配布。*

## Overall verdict

コアの命題(優先度が表示に効く)がはっきりしていて、機能・指標・非目標がその命題に沿って並んでいる。UX / アーキテクチャ / ストーリー化に渡せる水準。リスクは (1) FR-9 選抜ロジックの詳細が [ASSUMPTION] のままで、UX と実装の見え方を左右すること、(2) データ保管方式(§9-4)を意図的にアーキテクチャへ丸投げしており、それ次第で §4.5 の FR が変わりうること。どちらも文書内で明示されており、隠れた穴ではない。

## Decision-readiness — adequate

トレードオフは概ね正直に出ている。ウィジェットを v1 から外した判断は理由(OS ネイティブ機能)と代替(FR-10 コンパクトビュー画面)つきで、`[NOTE FOR PM]` も「コアの動機に直結するのでスマホ展開を早める価値」と実際の緊張点に置かれている。Open Questions は本当に開いている(次の文で答えを出していない)。

### Findings
- **medium** データ保管の非決定 (§9-4, §4.5) — 「おまかせ」でアーキテクチャに委ねているが、クラウド/ローカルの選択で FR-16(ログイン)・FR-17(エクスポート)・複数端末同期の有無が変わる。*Fix:* アーキテクチャ工程の最初の決定事項として明記済み。UX 着手前に確定するのが望ましい旨を §9-4 に追記すると尚可。
- **low** 課金モデル (§9-6) — v1 無料は確定だが将来像が未定。この規模では許容。

## Substance over theater — strong

ペルソナ濫用なし(UJ 3本、いずれも名前つき、各 UJ が具体的な決定 ── 優先度づけ、選抜、シフト入力フロー ── を駆動)。差別化は Discovery で出た実在の不満(狭い画面で埋もれる)に根ざしており、テンプレ埋めではない。Vision はこの製品固有(他のカレンダー PRD に流用できない)。NFR は §8.3 に製品固有の項目(最小スコープ・読み取り専用・接続解除でデータ削除)として書かれ、ボイラープレートではない。

## Strategic coherence — strong

命題が明確で、機能の優先順位がそれに従っている(コア = §4.2、その他は支える位置)。SM は活動量ではなく命題を検証する形(SM-2「最優先が埋もれず先頭」= FR-9 の検証)。反指標 SM-C1/C2 が「設定項目を増やして柔軟に見せる」「給料計算を膨らませる」という、この製品が最も陥りやすい失敗を名指ししている。

## Done-ness clarity — adequate

ほとんどの FR に検証可能な consequence がある。FR-13(日またぎ通算)・FR-14(暦月・複数時給合算)・FR-9(今日以降のみ・0件時の表示・選抜1箇所実装)は特に明確。

### Findings
- **low** FR-7 / FR-10 — 初稿の「より目立つ」「大きめの活字」を、Finalize で「左端に置く/前面」「低い情報密度で1件ずつ」に具体化済み。残る曖昧さは UX スペックで詰める範囲。
- **low** FR-1「一定時間 Undo を提示」 — 秒数未定。ストーリー化時に確定で可。

## Scope honesty — strong

Non-Goals(§5)が実際に働いている(チーム向け・タスク管理・編集クライアント・給与ソフト・ウォッチネイティブを明示排除)。`[ASSUMPTION]` は推測箇所すべてに付き §10 に索引化、ラウンドトリップ成立。`[NOTE FOR PM]` は本当の緊張点(ウィジェット de-scope)に配置。

Open-items 密度: Open Questions 7 + `[ASSUMPTION]` 約6 + `[NOTE FOR PM]` 2。UX 前段階の個人プロジェクト PRD としては許容範囲。build ゴーサインの PRD なら要削減だが、ここはその段階ではない。

## Downstream usability — strong

用語集(14語)完備、FR/UJ/SM で用語が一致。ID 連番: FR-1〜17、UJ-1〜3、SM-1〜5 + C1/C2、いずれも欠番・重複なし。相互参照(§8.3、§9-1〜6、FR-N、UJ-N)は Finalize で dangling(旧「§Constraints」)を解消済み、全て解決する。各節は単独で抜き出しても意味が通る。

## Shape fit — good

消費者向けプロダクトとして UJ が主役、過剰形式化なし。個人プロジェクトゆえ厳密さは軽め、実体の水準は保っている。Platform を Adapt-In で追加したのは妥当(Web 先行 → スマホ → ウォッチの段階が命題に直結)。

## Mechanical notes

- **用語ドリフト**: addendum のシフカレ節に「バイト先」があるが、これは競合機能の引用であり PRD 本文は「勤務先」で一貫。問題なし。
- **ID 連続性**: 問題なし(上記)。
- **Assumptions Index ラウンドトリップ**: 本文 `[ASSUMPTION]` 7箇所 ↔ §10 索引 7項目、対応が取れている。FR-16 は1行に2つの前提(アカウント方式・お試し利用)をまとめているが許容。
- **UJ 主人公命名**: UJ-1/2 = 圭太、UJ-3 = 美咲。全 UJ に名前つき、文脈がインライン。
- **必須セクション**: Essential Spine 全項目 + Platform/Constraints。stakes 相応。
