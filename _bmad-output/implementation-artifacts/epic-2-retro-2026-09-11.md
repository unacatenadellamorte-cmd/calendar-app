### 集約ビュー: spec ⇔ 実装の突き合わせ

**F1 ── FR-7 の後半(「並べきれない場合は前面に」)が未実装** ── 重み: 低

- FR-7 / epics.md 2.3 AC1 / UX-DR5:「優先度が高いカレンダーのものを左端に置き、**左右に並べきれない場合は優先度が高いものを前面にする**」。
- 実装: `layoutDayEvents`(`src/lib/calendar-view.ts`)は列数に上限を設けず常に左右タイル(列幅 = 100 / 列数 %)。列が細くなっても必ずタイルできるので「並べきれない場合」に到達しない。z-index による「前面」表示は無い。
- FR-7 の2つ半のうち「左端」だけが実装済み。`deferred-work.md`(spec-2-3)に「列キャップ + z-index 付与 + WeekView のスタック描画」として記載済み。個人カレンダーで4件以上の同時重なりは稀。
- **disposition: defer(追跡済み)**

**F2 ── ドラッグ並べ替えは実機未検証(HTML5 DnD のみ、タッチは ▲▼)** ── 重み: 低

- 2.1 AC1「行をドラッグして並べ替える」。実装は全 `<li>` に HTML5 DnD(デスクトップ)+ ▲▼ ボタン(モバイル / キーボード / SR)。スムーズなタッチドラッグ・`@dnd-kit` は `deferred-work.md`(spec-2-1)。
- 本セッションの Phase C は ▲▼ で検証(並べ替え + ランク即再描画 + SR「優先度 N/M」)。HTML5 DnD のドラッグ操作そのものは実機で叩いていない。
- **disposition: accept(デスクトップ DnD 実装済み・モバイルは ▲▼ が堅い経路。追跡済み)**

### 集約ビュー: パターン乖離 / テスト構造

**F3 ── 採番トリガ + 列 default の非互換がレビューをすり抜け、実 DB 接続まで潜伏** ── 重み: 中

- Story 2.1 の `20260908000000_calendar_priority.sql` が `calendars.priority` に `default 0` を付けたため、before-insert トリガ `calendars_set_priority()` の `if new.priority is null` が常に false → 採番されず、2件目以降のカレンダーが `priority=0` で `calendars_priority_uniq`(部分ユニーク)に衝突して**作成失敗(23505)**。
- 2026-09-10 に実 DB(接続済みプロジェクト)で発覚 → `1cccad2`(移行 `20260910000000` で `drop default`)。Epic 2「done」から数日、Epic 3 の準備中。
- **コミットメッセージが自己診断している**:「Docker 無しで supabase start できず、Story 2.1 時点で migration は目視レビューだったため検出漏れ」。
- 真因: ローカル DB 統合テストがゼロ。「列 default が before-insert トリガより先に評価される」は SQL の基本挙動だが、目視レビューでは見落とした。Epic 1 F4(CSS レイヤー)と同じ「単体テストで検出不能な層の回帰が数日残る」パターン。
- **disposition: fix-now(済)+ プロセス:** Epic 1 retro AI-3 / Epic 3 retro AI-3 と統合(バックエンドのテスト方針)
