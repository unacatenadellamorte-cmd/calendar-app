## 分析(Phase 2)

diff-scope レビューはインライン実施(`bmad-review` は使わず、ストーリー境界に絞ってインライン。独立モデルの反証なし ── narrowing)。挙動検証は本セッションの Phase C で全7ストーリーを実 Supabase + 実ブラウザで end-to-end 実施済み(検証記録参照)。

### 集約ビュー: spec ⇔ 実装の突き合わせ

**F1 ── 初回・データなしの空状態(2入口)が未実装** ── 重み: 低

- epics.md 1.3 AC3 / UX-DR13:「初回・データなし → 『カレンダーを接続』『予定を追加』の2入口」。
- 実装: `HomeScreen.tsx` に空状態の分岐なし。`CompactCard.tsx:21` の「この後の予定はありません」のみ。シフト用カレンダーが常在(1.3 AC2、削除不可)するため「カレンダー0」は正常運用で到達不能、かつホーム見出しの「カレンダーの並び順 ›」+ カレンダー画面の「予定を追加」で機能的には塞がっている。だが UX-DR13 の状態パターンを1つ落としている。
- **disposition: defer**(オンボーディングを触るストーリー、または UX 微調整でまとめて)

**F2 ── `deleted_at IS NULL` が共通ヘルパでなく各クエリ個別指定** ── 重み: 低

- epics.md 1.4 AC3 / 規約:「全読み取りクエリは共通ヘルパで `deleted_at IS NULL` を強制」。
- 実装: `src/data/calendars.ts:107` / `src/data/events.ts:187` / `src/data/shift-templates.ts:159` それぞれに `.is('deleted_at', null)` を直書き。invariant は保たれているが「1か所で強制」ではなく「3ファイルで規律」。新しい読み取り経路を足すとき付け忘れうる。
- **disposition: defer**(小さなヘルパ or lint ルール)

**F3 ── UX-DR16 / UX-DR17 の一部が未実装** ── 重み: 低

- 月/週の横スワイプ日付移動(UX-DR16)、PC 幅で月ビューを広く(UX-DR17)── どちらも `deferred-work.md`(spec-1-5 / spec-1-1)に記載済み。スワイプは jsdom でテスト困難、PC 幅対応は `AppShell` の `max-w-2xl` 固定。個人スマホ利用が v1 主対象で実害小。
- **disposition: defer**(追跡済み)

### 集約ビュー: パターン乖離 / テスト構造

**F4 ── レイアウト/CSS レイヤーの回帰がレビュー + テストをすり抜け、3日後に実機で発覚** ── 重み: 中

- Story 1.1 の `global.css` 自前リセット(`* { margin:0; padding:0 }`)が `@layer base` の外にあり、Tailwind v4 の `@layer utilities`(`mx-auto` / `px-*` / `mb-*`)を全部上書き。アプリシェルの中央寄せ・内側余白が壊れていた。
- 2026-09-10 に実ブラウザで発覚 → commit `b888a15` で修正。Epic 1「done」から約3日、Epic 2 の途中。
- 真因: **jsdom はレイアウト/カスケードを解釈しない** → 単体テストで CSS レイヤー事故を検出できない。3レンズレビューも見逃した。Tailwind v4 preflight が既にリセットを持つことも見落とし。
- **disposition: fix-now(済)+ プロセス:** CSS を触るストーリーは実ブラウザでのスモークを必須にする(F7 と同じ結論)

**F5 ── コミットワークフローが途中で変わった** ── 重み: 微

- 1.1〜1.4 は main へ直接コミット(merge commit なし)、1.5〜1.7 は `story/*` ブランチ + merge。`git_evidence.py` の commits を見ると明白。
- 実害なし(履歴は追える)。BMAD build のブランチ運用が 1.5 から定着したと読める。以降のエピック(2〜4)は全ストーリーがブランチ + merge。
- **disposition: accept(以降そろっている)**
