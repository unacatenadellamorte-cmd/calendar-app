## Intent

**Problem:** 本人によるTestFlight 1.0.25（29）の確認で、撮影のキャンセルは成功したが、プロフィール画面に戻るボタンがなく、カレンダーと設定を経由する回避操作が必要だった。プロフィール編集画面から分かりやすく戻れるよう修正する。

**Approach:** プロフィールのヘッダーに文字付きの戻る操作を追加する。購入・復元・写真撮影と保存、初回登録の動作は変えず、既存の翻訳と画面部品を利用する。ストア更新や新しい配布はこの局所修正に含めない。

## Implementation Notes

- 2026-10-20：本人が「この対象で進める」と回答。公開検査境界はプロフィールの表示と実際の画面遷移、戻り先は元の画面、不明時は設定として承認を受領した。
- 調査：`src/features/profile/ui/ProfileScreen.tsx`は通常・読み込み・利用不可のどの分岐にも戻る操作がない。`src/ui/Screen.tsx`の`action`枠を再利用でき、共通画面部品の改変は不要。
- 入口は`src/app/AppShell.tsx`の上部アバター（遅延した単一タップと通常リンク）と`src/features/settings/ui/SettingsScreen.tsx`のプロフィールリンク。`src/app/routes.tsx`の`/profile`へ遷移する。アバターのダブルタップ動作は維持する。
- 提案する戻り先は開く前のアプリ内画面、不明時は設定。実装前にTDDの公開検査境界と戻り先を本人へ確認中。未確認のまま新しいテストや製品コードは書かない。
- 検査候補はプロフィール画面と実際のルーターを組み合わせた表示・操作・遷移。内部のnavigate呼び出し回数は新しい検査の根拠にしない。既存プロフィールの保存と言語切替の検査も維持する。OSの撮影・課金成功はこの検査で代用しない。
- iPadの29受入は別の既存審査対応で継続し、写真ライブラリの日付別一覧は本人の選択どおり別機能版へ分けたままにする。
- 承認後の実装：上記の「確認中／まだ書かない」は調査時点の停止点で、本人の承認により解消。`ProfileScreen.tsx`の全表示状態に戻る操作を設置し、アバターと設定一覧から元のURLを渡す。通常操作は元の履歴へ戻り、戻り先不明時だけ設定へ置換する。修飾キーや別タブ操作は通常のリンク動作を維持する。共通Screen・プロフィール保存・課金・撮影の処理は変更しない。
- TDD：戻るリンク不在の失敗→設定への復帰成功、アバターからの復帰失敗→元画面への復帰成功、言語切替で戻る表示が未翻訳の失敗→既存5言語辞書へ追加後成功。独立確認後も履歴重複を実ルーターで再現し、カレンダー・設定の両入口で後続の履歴戻りまで成功させた。カレンダーの日付クエリとハッシュも検査する。
- 検査用のデータルーターは環境のRequest/AbortSignalの型不一致を起こしたため採用せず、既存のMemoryRouterと公開フックによる履歴操作を使用した。補助のURL表示・履歴操作は該当2試験だけに出し、既存のstatus検査へ混入しないようにした。
- 本人の追加承認「試験の日時固定も進める」に基づき、`src/features/compact/ui/CompactCard.test.tsx`だけを補強。実行日が固定予定の10月20日と一致して別日条件が崩れた失敗を単独でも再現し、Dateだけを10月19日に固定して6件成功。タイマーを復元し、アプリ本体の表示仕様や期待値は変えない。
- 最終検証：`npm test -- --maxWorkers=4 --reporter=dot`で168ファイル1,645件成功。関連8ファイル74件はseed 20261020の順序変更でも成功。型検査成功、静的検査はエラー0・既存Fast Refresh警告1。WebビルドとiOS向けWebビルド成功、後者のJavaScript8ファイルのGoogle Play文言・URL混入0。既存のimport混在・チャンクサイズ警告は残る。新しい署名済みIPAや実端末での戻るボタンの受入確認を意味しない。
