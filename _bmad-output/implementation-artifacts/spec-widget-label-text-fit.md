## Intent
月・週ウィジェットの予定文字の下側が切れるため、文字サイズを小さくし、予定タイトルの先頭4文字まで見えるようにする。

</frozen-after-approval>

## Implementation Notes
- 不明点・不可逆な変更なし。月週共通のWidgetCalendarCells.ktの本文のみ10spから8spへ変更し、行高12dpは保つ。日付・ヘッダー・日のウィジェットは対象外。
- CalendarOverview.ktの行容量コメントも実サイズへ合わせる。予定順・件数・色・ナビゲーション経路は変更しない。
- 実描画で日本語4文字とフォントの上下がラベル内に収まるか確認し、Androidビルド後に接続端末へ更新する。既存の未追跡資料は今回も触らない。

- 8sp固定だけでは幅320dpの外部予定で4文字目が省略されたため、7列の有効幅から上限文字サイズを計算する方式へ補正。本文4文字・省略記号・外部色マーカーの幅を確保し、基本8spと小さい方を採用。部品数と行高は増やしていない。
- Android単体35件とビルド成功。実描画テスト1件成功（14.939秒）。OS文字倍率1.3・アプリ1.2を組み合わせ、週180/320dp、月250/320dpで自作と外部の日本語4文字・縦方向・祖先領域内への収まりを検証。380dpでは色・月末・全自作の月移動1秒以内も検証。エミュレーターの文字倍率は元の1.0へ復元。
- 接続端末へ上書きインストール成功、アプリ起動済み。画像は共通の出力画像/20260926_widget-text-fit-month.png・week.png（拡大設定の検証用予定）。実機上の今回の表示を直接観察したという意味ではない。

## Review Triage Log
- 最小対応幅で4文字が収まらない: medium。固定8spでは実際に320dpで失敗。幅に応じた縮小を追加し、週180dpと月250dpも実描画で成功。
- 拡大設定の検証不足: medium。OS1.3倍・アプリ1.2倍の組合せで4文字と縦の収まりを確認。幅上限の計算にOS倍率を含める。
- 文字自身の高さ比較だけでは親のクリップを検出できない: medium。既存のfindBoundedTextを組合せ、祖先すべてとの境界比較を追加。月の全自作・月末確認も既存テスト内で継続。
