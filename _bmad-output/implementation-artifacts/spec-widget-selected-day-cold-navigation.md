## Intent
「日」は選択日の予定だけを表示し、▲▼で日を切り替える。月・週で再発した切替待ちを修正する。
</frozen-after-approval>

## Implementation Notes
- 通常のグリッドと予定色・並び順を維持。日の選択日を追加リンクにも反映する。
- 前回の速度検証は稼働セッションの直後のみ。今回、55秒以上の非操作後の切替も検証する。
- 日付のSimpleDateFormat生成を数値検証へ変更、共有JSONの解析結果を再利用する。
- 保存・描画をウィジェット単位で直列化し、Glanceの通常更新と直接のRemoteViews生成で待ちを減らす。リストの古いAndroid対応は通常更新を維持。
- 開始コミット a692c090efdbfd0b6da49f71e9324a4fdfd72c2e。変更対象はAndroidウィジェットと関連テスト。

- 稼働中はStateFlowで選択日を渡し通常セッションを再利用、停止中はcompose→AppWidgetManagerで即時生成する方式へ調整。常時二重描画していた試作は廃止した。
- 単体テスト、実描画4件（106.346秒）成功。55秒非操作後は月750ms・週742ms・日734ms。日連続▼▼▲の最終日保持を2秒間確認。日同日8件スクロールと複数配置独立性、実Intent操作も検証。
- 実機でプロセス終了からの開始を測定。月描画約621ms、マーカーから更新呼出しまで約1.23秒。通常の描画処理505〜785ms。全状況で1秒以下との断言はしない。
- 実機Smart Launcherでは22:48以降AppWidgetHostの更新受信ログが停止しており、アプリ側の更新ログ・永続オフセットだけが進む状態だった。ホームアプリを再起動して受信復旧、実機上で月→9月、週→9/20–26、日→25日に戻ることを確認。
- 日の最終実機表示は25日(金曜日)、予定2件のみ。翌日へ移動した際は26日(土曜日)のみになった。端末へ更新APK導入済み。
