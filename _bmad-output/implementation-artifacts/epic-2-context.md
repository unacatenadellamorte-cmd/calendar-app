# Epic 2 Context: 優先度をつけて、大事な予定を先に見る

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

カレンダーごとに「優先度」を並べ替えで設定でき、それが表示のあらゆる場所に効くようにする ── カレンダー一覧・予定リストの並び、月セル内の積み順、週タイムラインの重なり順、そしてホームのコンパクトビュー(この後の代表予定)。数値やウェイトを刻ませず「順位ひとつ」に絞るのがこのアプリの勝ち筋で、Epic 2 でそれを自分のカレンダーだけで完成させる(取り込んだカレンダーにも同じ仕組みが効くよう、優先度は取り込み前提で設計する)。

## Stories

- Story 2.1: カレンダーの優先度設定(ドラッグ + キーボード)
- Story 2.2: 優先度ユーティリティと一覧・リストの並び
- Story 2.3: 重なった予定の視覚的な優先表示(週・月)
- Story 2.4: 代表予定の選抜ロジック(packages/core)
- Story 2.5: ホームのコンパクトビュー

## Requirements & Constraints

- 優先度 = 並べ替え。カレンダー管理画面で行の順序を変えることで設定する。数値入力・重み設定は作らない。順位はユーザーの全カレンダーで一意。
- 新しく作る / 取り込むカレンダーは既定で最下位の優先度に入る。表示オフでも優先度は保持する。
- 並べ替えはドラッグが主、**キーボード / ボタンの代替(行にフォーカス →「上へ / 下へ」)を必ず用意**する。スクリーンリーダーは「優先度 2/5、上へ移動可能」のように現在地と操作を読む。順位は番号でも表す(色だけに意味を持たせない)。
- 優先度を変えたら**再読み込みなしで**並び・描画が即反映される。
- 並び順への作用: カレンダー一覧・リストビュー・コンパクトビュー・月セル内の積み順・週タイムラインの重なり順、すべて優先度順。同順位内は開始時刻順。
- 視覚的な優先: 週で時間が重なる予定は優先度の高いカレンダーを左端 / 前面に。月でセルに入りきらない時は優先度が高い予定から見せ、あふれを「他 N 件」に畳む。「他 N 件」を開くとその日の全予定を優先度順(同順は開始時刻順)で見られる。
- 代表予定の選抜規則(5つ、この順): (1) 現在時刻以降 / 進行中のみ (2) 優先度が高いカレンダーが先 (3) 同カレンダー内は開始時刻順 (4) 終日は時刻付きの後 (5) `limit` で打ち切り。対象0件なら空を返す。
- コンパクトビューは低い情報密度(1件ずつ独立した行)、各行にカレンダー名・色・開始時刻。表示件数は設定で 1〜3(既定3)。予定タップでカレンダーの該当日へ。この後の予定が無ければ「この後の予定はありません」を1行で静かに(感嘆符なし)。
- トーンは静か。達成演出・ストリークを入れない。

## Technical Decisions

- **優先度は単一の整数順序値**。`calendars` に `priority` 列を追加し、`(user_id, priority)` を一意にする(部分ユニーク: `deleted_at is null`)。採番・並べ替えは**1つの DB 関数(RPC)経由**でのみ行い、フロントも(将来の)取り込み Edge Function も同じ関数を呼ぶ。UI がその場で priority を計算しない。
- 一意制約を保ったまま並べ替えるため、RPC は1トランザクション内で「退避オフセットへ一括 → 指定順で再採番」の二段で更新する(単発 UPDATE の途中衝突を避ける)。新規行の最下位採番は `before insert` トリガで行う(フロント / Edge Function 双方をカバー)。
- **並び規則は `packages/core` の純関数に集約**(Story 2.2)。`selectFeaturedEvents(events, calendarPriority, now, limit)` も `packages/core`(Story 2.4)。副作用・I/O なし、`now` は引数(内部で現在時刻を読まない)、正規入力型(camelCase / UTC)は core が定義。呼び出し側が自分の表現から変換して渡す。`packages/core` は何も import しない葉。
- 「一覧の並び」「重なりの描画順」「代表予定の選抜」はすべてこの優先度ユーティリティを通す。UI・view-model は並べ替えロジックを書かない。
- 全体規則は「優先度 → 開始時刻順」で実装する([ASSUMPTION]: 対案「優先度 → 今から近い順」は PRD の未解決論点。選抜関数の内部実装として差し替え可能に保つ)。
- data-access は `Result<T, AppError>` を返す。書き込みは data-access リポジトリ関数のみ。楽観更新 → 失敗ロールバック。オフラインは outbox キュー(Story 1.6 の仕組み)。
- テスト: `packages/core` の並び規則・選抜規則は単体テスト必須。

## UX & Interaction Patterns

- **calendar-row**(カレンダー管理): 順位番号 + ドラッグハンドル + 色ドット + 名前 + source(ローカル / Google)+「▲ 上へ / ▼ 下へ」+ 表示トグル。行タップ → 改名・色・(Epic 3 で)接続解除。シフト用カレンダーも並べ替え対象(削除は不可のまま)。
- 画面見出しは「カレンダーの並び順」。補助文「上にあるカレンダーほど優先。狭い表示や重なったときに先に出る。」。ホーム見出しからも設定からも1タップで開ける(下タブには入れない)。
- **compact-card**(ホーム): 代表予定を優先度順に最大3件、1件ずつ独立した行。予定タップ → カレンダーの該当日。引っ張って更新。
- **month-cell / week-timeline**: 積み順・重なり順が優先度順になる(Story 2.3 が現行の開始時刻順ロジックを差し替える)。
- アクセシビリティ: すべての操作要素に役割 + 状態のラベル。並べ替えはキーボードで完結でき、スクリーンリーダーが現在地と可能な操作を読む。コンパクトビューの読み上げ順 = 優先度順。44px 以上・フォーカスリングを消さない・Reduce Motion 尊重。

## Cross-Story Dependencies

- Story 2.1(`priority` 列・RPC・トリガ・並べ替え UI)がこのエピックの前提。2.2 以降は 2.1 の上に載る。
- Story 2.2 の `packages/core` 優先度ユーティリティを 2.3(重なり描画)と 2.5(コンパクトビュー)が使う。2.4 の `selectFeaturedEvents` を 2.5 が使う。
- Story 2.3 は Story 1.5 の月 / 週ビュー(`layoutDayEvents` / `groupEventsByDay` / MonthView の「他 N 件」)の描画順・畳み順を優先度順へ差し替える。
- **Epic 3(Google 取り込み)は Story 2.1 の `priority` 列に依存**(取り込んだカレンダーも最下位優先度で入る)。Epic 4 は Epic 2 に依存しない。
- 取り込み Edge Function(Epic 3)も採番 RPC / トリガを共有する。
