# Playデータセーフティ調査（2026-09-26）

申告準備の資料。データセーフティの最終申告・審査提出は未実施。

## アプリ実装から確認した収集

|申告候補|保存先・目的|任意性|
|名前|Supabase profiles.display_name、プロフィール表示|オンボーディングに必要。実名である必要はない|
|メールアドレス|Supabase Auth、認証・アカウント管理|メール登録時のみ。匿名モードあり|
|ユーザーID|Supabase Auth・各テーブルの所有者識別|匿名モードを含む基本利用で生成|
|写真|Supabase profiles.avatar_data_url、プロフィール画像|任意選択|
|カレンダー|Supabase calendars/events、予定・日時・メモ・場所・URL・通知設定、同期|ユーザーの作成・取込み操作による|
|その他の金融情報（候補）|時給・勤務情報・シフトテンプレート、給与見積り|シフト機能利用時|
|その他のユーザー生成コンテンツ（候補）|タグ、表示設定など|機能ごとに確認|

予定の場所文字列はGPS取得ではない。端末のGPS・マイク・連絡先権限は実装から見つからなかった。

端末カレンダーは読取り専用だが、選択した予定をSupabaseへアップロードする。端末内処理だけという申告は不正確になる。Google連携の予定もGoogle APIからSupabaseへ取り込む。

Supabaseへの送信は機能提供・認証のため。Playのサービスプロバイダへの共有免除の定義に照合すること。「第三者へ一切送らない」とは表現しない。

## 広告SDK

AdMob以外のFirebase Analytics、Crashlytics、Sentry等の分析SDKは見つからなかった。Google Mobile Adsの公式説明は、IPアドレス、操作情報、診断情報、端末・アカウント識別子を広告・分析・不正防止のため収集・共有すると説明している。IPによる推定位置も対象になる。

- 広告ID申告: 使用あり。用途は分析、広告・マーケティング、不正防止・セキュリティ。
- データセーフティ候補: おおよその現在地、アプリ操作、診断情報、デバイスまたはその他のID。利用SDK版と正確な診断サブ項目を照合して最終化する。
- 通信はTLS。広告IDはAndroid設定で削除できる。これを全収集データが任意という意味に広げない。
- 公式資料: https://developers.google.com/admob/android/privacy/play-data-disclosure
- Play定義: https://support.google.com/googleplay/android-developer/answer/10787469?hl=ja

## 未完了条件

- アカウント削除用の公開URLが必要。現行ポリシーはPlay掲載の窓口参照だけで、未公開の現状では削除案内として不十分。
- 設定画面に本人用削除導線がない。削除対象にVaultのGoogle認証情報と端末キャッシュ・未送信操作・通知・ウィジェットを含める必要がある。
- 運用上のバックアップ保持期間は未確認。架空の日数を記載しない。
- Google OAuthはカレンダー接続であり、現行アプリへのログイン方法としてOAuthを自動的に選択しない。
- 実装とバックエンド反映、公開案内の検証後にデータセーフティを完成させる。

削除要件の公式資料: https://support.google.com/googleplay/android-developer/answer/13327111?hl=ja

## 審査用アクセス

Playは審査担当者による新規登録・個人アカウント利用を不可と表示。ゲストだけで全機能へアクセスできるとは申告しない。
ユーザーが専用アプリ用アカウントの作成とPlay審査担当者への登録を承認。アカウントを作成しログイン確認済み。ブラウザ制約でパスワード入力はユーザーへ引き継ぐ。Google連携の専用アカウントは未準備と回答された。登録用フォームは未保存。
