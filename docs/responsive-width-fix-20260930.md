# 端末幅に収まる画面への修正

## 再現と変更

320pxの画面で、シフト登録の時給欄の右端が約418pxまで広がることを再現した。flex子のlabelと入力欄の固有幅が縮まず、入力用シート内で横スクロールが発生していた。

- フォーム、label、入力欄に縮小可能な最小幅と最大幅を設定した。
- 編集可能な入力欄の文字を16px以上とし、iOSの入力フォーカス時の自動拡大要因を解消した。viewportのピンチ拡大は禁止しない。
- ページの横方向のはみ出しと引っ張りを抑え、月送りのtouch操作と縦スクロールを保持した。
- 共通画面、固定下タブ、入力シートへ左右のsafe-areaを適用した。
- 表示切替を等分幅にし、日付見出しは幅内で折り返す。日付移動入力は独立した全幅の行に配置した。

## 確認

- Chromeの幅320、375、390、430、768、844、1024pxで月カレンダー、シフト入力、予定入力を検証。844pxでは高さ390pxの横向き相当。
- ドキュメントと本文・入力シートでscrollWidthがclientWidth内、入力欄が画面外へ出ないことをDOMの矩形でも確認。シフト入力は320pxで時給欄も収まり、スクリーンショットを目視確認した。
- 幅320pxで年・日・リスト表示、日付移動、設定画面も確認。入力文字は16px。
- 型チェック成功、関連7ファイル130テスト成功。日付入力行移動後にDateNavの7テストを再実行し成功。lintはエラー0、既存警告1件。
- 独立レビューはCSS優先度、safe-area、縦スクロール、月送り、広告座標、フォームの6観点で指摘なし。
- ブラウザ検証用の新規匿名プロフィール「画面幅の動作確認」を使用。個人予定の操作・削除は行わない。
