## 撮影と作成の方法

- アプリの共通画面は現行distを使い、ローカルの撮影専用APIと架空の予定を表示して撮影。
- ウィジェットは最新Android実装をエミュレーターのAppWidgetHostで描画。
- 説明文と背景は既存素材のHTML/CSS方式を更新。画面内の予定・入力欄を描き直したものではない。
- 実際の利用者のアカウントや予定は使っていない。Google Playへアップロード・公開はしていない。
- 画面はサンプル。給料の表示は架空の勤務条件から計算した目安。

## 再作成

1. preview_server.pyを起動し、healthでlocal-fixtureであることを確認。
2. /captureラッパーで共通画面を撮影。iframe内はモバイル幅412px、2倍で描画。シフト編集のみcapture-wide.htmlの480px幅を使用。読み込みが終わり、予定が見えることを確認してから撮影する。
3. build_layouts.pyで掲載用HTMLを作成。
4. ブラウザでstore-01.html〜08.htmlを1080×1920、feature.htmlを1024×500で描画・撮影する。
5. contact.htmlを1600×1540で撮影して一覧を確認。package_assets.pyで寸法・PNG形式・ファイル容量・ZIP内容を検証し、ZIPと素材一覧.htmlを作成する。

StoreCaptureTest.ktは撮影用の再現資料。本番ソースには追加せず、一時ビルド環境のandroidTestへ置き、エミュレーターのシリアルを指定して実行する。今回の最終撮影はemulator-5554で1件成功し、月・週・日の3画像を確認した。初回の接続デバイス一括テストが物理端末にも走ったため、以降はエミュレーターを明示指定した。

## 確認結果

- 完成画像8枚・紹介画像・現行アイコンの計10点を検証。画像の寸法・色形式・容量・SHA-256は成果物検証.jsonに記載。
