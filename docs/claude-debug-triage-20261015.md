## #4のメモリー内再現

既存SQLをPGliteへ適用し、合成ユーザーA/Bと合成Vaultを使用した。本番接続なし。

1. authenticatedロールのAが、provider=device・vault_secret_id=Bの合成秘密IDの接続をINSERT。
2. AのJWTでdisconnect_google_connectionを呼ぶとBの合成Vault行が0件になることをassertで確認。
3. AがBの接続ID・既知external_idを指定してGoogle予定をAのカレンダーにINSERT。
4. Bのapply_calendar_sync後も所有者はAで、Bの合成タイトル・メモに変わることをassertで確認。

これは「参照列を全面禁止すればよい」という結論ではない。Epic5 AD-17は本人deviceの直接書き込みを明示する。source=deviceは接続・カレンダー・所有者の一致を検証して許可し、source=googleの保護対象列をクライアントが変更しないようにする。既存の取り込み予定へのリマインダー変更も維持する。deviceのVault参照はDBで禁止し、解除・アカウント削除の秘密削除対象をgoogleに限定する。
