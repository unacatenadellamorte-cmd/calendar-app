## 対応

- Androidの取り込み失敗は実機READ_CALENDAR未許可。ユーザーが設定で許可し、取り込み成功を確認。
- 予定取り込みとカレンダー一覧更新の前に端末の権限を確認し、未許可なら設定での許可を案内する修正をAndroid/iOS共通コードへ反映。
- 1.0.20 (23)の配布ビルドを起動。CI: https://github.com/unacatenadellamorte-cmd/calendar-app/actions/runs/36854480016
- 英文追記は ios-review-additional-info-20261001.txt。目的は個人の予定・勤務シフト集約。18歳以上、勤務者などが対象。給与見込みは本人入力からの参考計算で、給与振込・金融サービスではない。
- 外部サービスはSupabase、Google Calendar/Google Sign-In、Apple EventKit、Google AdMob、Apple通知・WidgetKit。AI・決済・課金・サブスクはない。
- 国による機能分岐はない。言語・タイムゾーン・広告供給や同意画面は異なり得る。初回EU配信なし。
- 予定や画像はアカウント内の私的データ。公開フィードや他ユーザーへの投稿・チャットなし。外部カレンダーは本人の許可で読み取る。

## 実機録画の手順

ユーザー申告の端末はiPhone 13 Pro、OS27.0。Apple公式情報では27.0.1が公開されているため、端末のソフトウェアアップデートで最新版を確認してから撮影する。TestFlightで提出用と同じビルドを使う。旧Sideloadly版との混同を避ける。

1. 実ユーザーの予定を入れない使い捨て撮影アカウントを用意する。共有のApple審査用アカウントは削除しない。
2. iPhoneの画面収録を開始し、ホーム画面からアプリアイコンを押して起動する。起動部分を省略しない。
3. 設定 → アカウント作成/ログイン → アカウントを作成する。メール認証が要求された場合は完了する。パスワードは隠したまま入力し、受信箱や別の個人情報は撮影しない。
4. ログアウト → 同じ撮影アカウントでログイン。
5. カレンダー作成 → 日付選択 → 時刻付き予定と終日予定を保存して表示確認。
6. シフトテンプレート作成 → シフト入力 → 色・翌日移動・給与見込みを表示。終日シフトは給与計算対象外であることを見せる。
7. カレンダー接続は架空予定だけの端末カレンダーで許可 → 選択 → 今すぐ取り込み → 表示確認。Google連携は専用Googleアカウントのみ使用して認可・取り込みを確認する。
8. ホーム画面へ戻りWidgetを追加 → 表示と日付タップでアプリへ戻る。広告バナーが操作部に重ならないことも確認。
9. 設定 → アカウントを削除 → 確認チェック → 完全に削除する。削除対象が撮影専用アカウントであることを確認して、本人が最終操作する。完了画面まで録画。
10. 実際の使用機種、OS、TestFlightのバージョン/ビルド、成功・失敗箇所を記録。録画ファイルを確認してからAppleへ添付/リンク登録し、返信と審査メモを完成させる。
